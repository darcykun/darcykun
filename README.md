#### `agent-workbench` — giving AI tools some boundaries

An experimental Python runtime for agent tool execution.

Instead of giving an agent unrestricted access and hoping for the best, this project explores a more deliberate approach: check permissions, keep operations in scope, and leave behind traces that help explain what happened.

| Inside the workbench | Why it matters |
| :--- | :--- |
| `tool approvals` | Actions can require explicit permission |
| `document scopes` | Tools only access approved locations |
| `execution budgets` | Runs have defined limits |
| `cancellation` | Execution can be stopped |
| `event traces` | Runtime behavior can be inspected |
| `automated tests` | Failure cases get tested too |

**[Source code](https://github.com/darcykun/agent-workbench)** · **[Documentation](https://github.com/darcykun/agent-workbench#readme)**

> My favorite kind of feature is the one that still behaves properly when everything around it goes wrong.
